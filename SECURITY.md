# Security reporting

Do not post vulnerabilities with exploit details, customer archives, credentials, license keys or session tokens in public issues. Use GitHub private vulnerability reporting if enabled; otherwise request a private reporting channel without disclosing sensitive details publicly. No email address is prescribed by this repository.

Include the version/build identity, affected component, a synthetic reproduction and impact. Review and redact diagnostics before sharing. Development previews have no promised security-support window; verified fixes and supported versions will be documented in release notes.
